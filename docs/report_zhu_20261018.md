# 短期进度报告：FloorSet / ICCAD 2026 Problem C（给朱老师）

日期：2026-10-18

朱老师，您好。我来汇报一下 FloorSet（ICCAD 2026 Problem C）课题这几天的进展，并想申请一点算力资源。

## 一、当前进度（对照官方成绩榜）

任务：给 21–120 个模块的布局问题，在硬约束（无重叠、面积区间、固定/预放置尺寸）全部满足的前提下，最小化线长、外接框面积与三类软约束违反（边界、分组、MIB 同形）；评分含运行时间因子。（这个其实朱老师知道）

路线：图神经网络提议 + 确定性后处理（凸优化与合法化构造），一次出解。

- 起步：最早的"端到端直接学布局"方案在小面板上 Q≈2.9–3.1，还不及一个简单的无训练解法（1.91），据此转向"模型提议 + 后处理保底"的路线。
- 现在：两组各 100 例开发面板上全部硬合法（100/100），平均质量分 Q＝1.22（越低越好）；单例推理+后处理约 1.2 秒，较上一版本的 10.5 / 12.7 秒快 8.7 / 10.1 倍。

与官方榜对比：官方 Beta 榜（8 月 23 日快照，隐藏 100 例）前十队伍质量分区间约 1.08–1.51，质量前三为 1.084 / 1.124 / 1.170。我们的平均 Q 已处于该区间中段；但口径不同（官方是隐藏集，我们是自建开发面板，但是做了训练集，验证集和测试集的划分），只作水平参照，不能推算名次。

目前一百万的数据集我们只使用了20000， 预计全部投入使用后模型性能会更佳。

## 二、一个关键发现：官方数据自身的约束冲突与标签质量

这两天我们专门核查了数据，有两个可验证的事实：

1. **官方参考标签并不优**：用官方评测器对两组开发面板共 200 例的参考解逐一打分，平均 Q≈1.30（1.2996 / 1.3029）；我们的求解器在 169 例（约 85%）上严格更优，平均低约 0.07–0.09。按照官方的说明，他提供的部分样例只是“较优解”，而非最优解。
2. **官方数据中存在数学上无法满足的约束组合**：MIB 软约束要求同组模块宽高相同，但不少组内模块的目标面积差异远超 ±1% 允许浮动（例如某例一组三个模块目标面积为 72/240/56），任何算法都无法让它们同形。固定开发 100 例中：99/100 例存在 MIB 违反（共 393 处），其中 374 处（约 95%）可证明不可避免；即使其它损失全部归零，该面板平均 Q 也不可能低于 1.18；MIB 占平均质量损失的约 90%。基本可以确认，这就是我们的Q不能进一步下降的罪魁祸首。

官方的QA里对此有非常模糊的说明，但是如果一个指标必须在95%的场景下被违反，那么他显然非常糟糕。

另外已重新核对过：本地训练数据与官方最新发布版本逐字节一致（含赛方"面积目标修复"版），排除数据版本问题。

我怀疑官方的隐藏测试集经过特殊修复，避免了这类约束自相矛盾的问题；这可能也是官方榜第 1、5、9 名的 raw_score（不考虑时间因子）表现更好的原因。

官方标签的平均质量明显低于我们当前求解器，而且以后这一差距可能更大。因此我们打算**用我们的求解器在官方数据上重新生成更优的监督数据**用于训练（数据侧自我改进，不改动官方数据、评分方式与提交形式）。
