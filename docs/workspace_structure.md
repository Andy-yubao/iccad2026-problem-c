# 工作区结构与文档管理规范

版本 1，2026-10-16 起采用。数据划分、评价口径和运行权限仍以 [执行协议](protocol.md) 为准。

**每个实验的代码、说明、配置与运行证据放在一起；复用数据集处理、官方输出评分和纯展示绘图。模型训练 Loss 不属于评分模块。**

## 1. 目录职责

```text
problemC/
├── README.md                  # 项目状态与入口
├── AGENTS.md                  # 简短工作边界
├── environment.yml
├── .gitignore
├── docs/                      # 五份可复用核心文档
│   ├── protocol.md
│   ├── workspace_structure.md
│   ├── datasets.md
│   ├── research_guide.zh-CN.md
│   └── git.md
├── experiments/
│   ├── README.md              # 实验索引
│   └── baseline/              # 当前唯一保留的硬约束基线
├── datasets/                  # 可复用的数据处理代码与唯一数据副本
│   ├── paths.py               # 路径解析、冻结训练索引
│   ├── cases.py               # 冻结 dev/公开面板、标签隔离与输入遮罩
│   ├── archives/              # 原始数据压缩包
│   ├── floorset_lite/         # 原训练数据，内部结构不改
│   ├── LiteTensorDataTest/    # 官方公开验证数据
│   └── *.json                 # 数据来源、原始安装证据
├── scoring/                   # 可复用的官方输出评分
│   ├── README.md
│   ├── official.py            # 原版官方评测器入口
│   ├── checks.py              # 独立硬约束复核
│   └── evaluation.py          # 官方原始计分及本地中性时间对照
├── visualization/             # 统一布局图样式，仅处理坐标/约束/已存指标
├── protocol/                  # 冻结 split_v1、workset_v2 与当前物理路径配置
├── scripts/                   # 数据/资料获取和工作区维护
```

没有实际内容就不建目录，不预设空的 `src/`、`configs/`、`reports/`、`figures/`、`tests/`。避免 `misc/`、`other/`、`selected/`、`new/` 等用途不明的分类。`archives/` 区分压缩包与可直接读取的数据；不再按“下载”动作增加一层目录。

## 2. 复用边界

| 模块 | 可以复用 | 不放入其中 |
|---|---|---|
| `datasets/` | 数据路径、冻结集合选择、原始样本读取、标签与合法输入隔离、基础格式适配 | 某种模型的图特征、增强策略、监督目标、采样训练策略 |
| `scoring/` | 官方 HPWL/bbox、约束违反、可行性、官方时间因子与总分，以及独立合法性复核 | Loss、正则项、可微代理、搜索候选目标、模型选择启发式 |

2026-10-17用户明确要求统一布局图：`visualization/` 保存从既有E6生成代码提取的纯展示模块，布局图统一调用；实验负责数据选择与读取，输出仍归各自runs。该模块不包含模型、Loss、构造、搜索、合法化或官方评分，不跨实验导入私有算法。

其余代码以实验独立为优先：模型、Loss、几何构造、合法化、搜索、训练和日志按需复制到各实验，分别维护，不再提取泛用公共目录。两条路线都需要矩形构造时，各自持有自己的 `packing.py`；修改一份不改变另一条路线。

同一实验的多次运行继续使用一套实验代码，通过配置和源码版本区分，不为每个 seed 复制代码。跨实验复制时在说明或源码快照中记录来源即可，不建立复杂的代码同步机制。

依赖方向是“实验 → 数据集处理/官方评分/上游”，以及实验内部引用。实验不得导入另一个实验的私有算法；数据与评分模块不得反向导入实验。跨实验使用权重直接引用其原运行文件与哈希，不建立重复的模型总仓库。

评分直接调用未修改的官方评测器。`score_official_output` 使用传入的实际耗时和匹配的官方中位时间；缺少正式评测所需基准时不能宣称得到比赛成绩。`evaluate_case` 延续本地中性时间质量对照：官方 runtime=median_runtime=1，实测时间另列，并复核既有输入合法性边界。该对照不能称为正式比赛总分。见 [评分接口](../scoring/README.md)。

模型专用 `data.py`、训练损失和代理目标仍留在实验内；它们与官方输出评分的职责不同。官方输出评分变化和 Loss 变化必须分别说明、分别验证。

## 3. 实验与运行

一个实验对应一个研究问题和连贯实现；配置、种子、预算、同一架构消融和排错是它的不同运行。主要假设、表示或求解流程根本改变时，再建立同级实验并注明继承关系。

```text
experiments/baseline/
├── README.md                  # 方法、用法、证据索引
├── design.md                  # 必要的实现与比较边界
├── optimizer.py
├── packing.py
├── run.py
├── plot.py
├── audit.py                   # 官方问题的诊断入口
├── diagnostics.md
└── runs/
    └── <run_id>/
        ├── config.json
        ├── results.json
        └── run.log            # 按需
```

简单审计只需 README、入口和 runs。2026-10-17用户要求当前及后续实验目录统一采用 `En_xxx`，例如 `E8_fast_robust_postprocess`，编号后用英文小写下划线描述机制；既有历史实验不自动搬迁。新运行名用 `日期_关键变量_seedN`，重跑追加 `_r2`。保留现有运行名，不覆盖已完成输出。预设配置被反复使用时才增加 `configs/`；实际生效配置始终留在运行内。

实验 README 说明假设与反例、参照/面板/指标/预算、执行与停止恢复方法、各运行结论和继续/淘汰原因。长架构写一份 design；长单次分析放对应运行的 analysis。不为同一内容反复生成阶段计划、首轮报告、摘要和交接报告。

| 运行文件 | 必需信息 |
|---|---|
| `config.json` | 实际命令、时间、源码版本、两类复用模块与上游版本、环境/设备、解析后的数据路径、划分哈希、面板、种子、预算、对照与来源运行 |
| `results.json` | 完成/异常/资源停止状态，实际时间和资源，样本数、指标与必要逐例证据；不可行例计入主指标 |
| 日志与其他产物 | 只保留排错、恢复、归因和复现所需内容；短检查可把日志信息并入结果 |

后续训练统一使用 [workset_v2.json](../protocol/workset_v2.json)：train 20,000、dev 2,500、封存 local_test 2,500，以及嵌套 train_monitor/dev_monitor 各 500 与 dev_quality 100。选择规格和训练策略以 [执行协议](protocol.md) 为准。运行 config 记录工作集哈希与监测参数，日志保存固定训练/验证曲线、学习率和停止原因；best 与 latest checkpoint 分别承担模型选择和完整恢复职责，不重复复制 checkpoint。时间上限停止与验证早停分开记录。

完整坐标只存一份，图片从该结果生成。不同时保存含相同 positions 的总结果、solutions 和逐例副本。不同实验可采用各自字段，不搭建统一实验框架。

运行必须可追溯源码。本地 Git 与 GitHub origin 连接；记录实际提交和未提交改动，同版运行引用源码提交，必要时补充小型源码快照。哈希不能代替源码恢复；历史缺少源码的限制如实保留。

## 4. 文档的唯一归属

`docs/` 只保留换一种算法后仍需阅读的核心内容：执行协议、结构规范、数据使用、通用赛题解读和 Git 使用约定。新内容优先并入已有文档；实验设计、当前瓶颈、分数、下一轮建议归实验。官方全文、官方论文和来源清单归 references；安装证据随 datasets。

| 位置 | 维护内容 |
|---|---|
| 根 README | 当前方向、关键结论的一两句概述与入口 |
| experiments/README | 每个实验一行状态与证据入口 |
| 实验 README | 假设、机制、比较、运行索引、下一步 |
| 运行 JSON/日志 | 精确数字、命令、计时、版本和停止事实 |
| AGENTS | 核心边界和规范入口，不记进度 |

数字以运行记录为准，不在多处抄完整表。新持久文件必须可从所属 README 找到；项目内链接用相对路径。文献中的作者报告、本地解读、本地实测及官方规则明确区分。

## 5. 数据位置与历史证据

`protocol/split_v1.json` 保持字节不变。其旧数据根字段是历史位置；当前读取统一通过 `protocol/paths.json` 解析，分片成员、顺序、面板、种子与划分哈希不变。路径移动不是重切分，不读取封存测试张量验证迁移，也不复制 train/dev/test 三套数据。

`protocol/workset_v2.json` 是原冻结集合内的工作子集索引，不替代、不覆盖 split_v1。后续新版本另存并说明原因；旧实验仍保留各自实际使用的成员与哈希，不批量改写为新规格。

官方加载器通过数据根参数读取 datasets，入口先检查本地文件，不能因路径错误触发自动下载；上游源码不改。

历史运行 JSON、日志、checkpoint、安装记录和源码快照中的命令、路径、哈希保持原样。当前说明可更新导航和可执行命令，并标注已迁移；历史调用事实以原始记录为准。资料清单若需改当前位置，保留原清单，不篡改来源 URL、原内容哈希或获取日期。

结构迁移记录集中保存在 `history/<日期>_workspace_migration/manifest.json`，包含旧新路径、必要文件校验和恢复方法；可修改的小型源码和文档保存一次迁移前快照。大数据同盘移动，通过文件清单/大小与已有校验记录验收，不重新下载、解压或反复全量哈希。旧归档保留原路径，恢复时结合迁移映射。

checkpoint 搬迁后只做必要读取兼容检查，不自动续训。用户后续执行恢复时记录源码变化、来源与累计预算；迁移后的源码哈希不同应明确审阅，不能静默放过恢复检查。

数据和资料旧位置见 [迁移映射](../history/20261016_workspace_migration/manifest.json)。用户明确要求清除旧方向时，连同源码归档中的相关实现一并清除，只记录清理范围与保留证据，不留隐蔽副本。旧文件归属不在规范里维护第二份表。

## 6. 每轮工作的最小流程

1. 开始：确定所属实验，写假设、参照和预算。预计训练/推理可能超过 20 分钟默认只交用户运行命令；仅在用户明确授权的特定任务范围内可由助手执行，参见执行协议。
2. 执行：输出到一个新 runs 目录，不覆盖完成记录；显式恢复时连续记录调用、源码变化、累计预算和停止原因。
3. 结束：运行目录保存事实，实验 README 写解释，实验索引更新一行；主线状态改变才改根 README，协议/接口改变才改核心文档。
4. 交接：保留活跃路线与有效参照；淘汰路线记录原因，必要代码、说明、结果及依赖版本一起归档到 history，确认可读后清除散落副本。

重复结果、空日志和可重建缓存不进历史。清理前核实运行状态和引用，不删除活跃输出、原始数据、有效环境、唯一 checkpoint 或唯一证据；不明用途先核实。日常代码检查默认最多 5 例相关短验证，不因搬迁重复全量实验，不自动启动未获授权的训练或续跑。用户批准的正式训练监测和阶段评价使用 v2 规模，不把五例代码检查上限误用为模型验证集规模。

验收标准：找到实验只需一个入口，找到精确结果只需一个运行目录，切换研究路线不会让 docs 随之膨胀。

## 7. Git 与 GitHub

主分支 main，远程 origin。日常提交、同步、入库范围与历史恢复见 [Git 使用约定](git.md)。只有明确请求恢复的已退役路线才重新引入，不从旧文档推断要续做的实验。
