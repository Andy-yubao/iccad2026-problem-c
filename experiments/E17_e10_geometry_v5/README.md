# E17：E10几何训练方法在当前v5数据上的对照

2026-10-20用户要求复用E10训练方法、采用当前数据，从头训练一次，训练结束自动验证500例，并明确授权助手后台启动。用户确认训练预算最多4小时或200轮，准备与终末验证另计。本实验不恢复E10旧训练或E16已停止任务。

训练和自动500例评价已完成并核对：第56轮早停、best第51轮，训练33分19.5秒；500/500最终硬合法，加权Q=1.060518、平均推理+后处理1.915333秒，未达到既定双目标。[完成分析](runs/20261020_e10_geometry_v5_seed0/analysis.md) · [检查证据](runs/20261020_e10_geometry_v5_seed0/completion_audit.json)。启动证据见[background_launch.json](runs/20261020_background/background_launch.json)，原流水线日志与结果保持原件，不自动续训此运行。

## 假设、数据与比较边界

检验持续的参考几何/结构监督能否避免E16监督衰减后原始质量代理恶化，并减少逐样本动态MST带来的训练开销。保留E10的497,299参数、宽96、4层attention、geometry训练损失及geometry+occupancy选模；使用当前冻结`reference_workset_v5.json`的train16,000/dev2,000，固定train/dev_monitor各500。seed0、随机初始化，不加载任何旧权重。原split_v1和所有旧索引不变；测试继续封存。

E10原训练为workset_v2的train20,000/dev2,500，当前v5按实际模块数均衡且输入做MIB平均面积修正，成员、规模及任务均不同。[成员对照](runs/20261020_background/data_comparison.json)仅读取train/dev索引元数据，登记两版重合数与v5模块数分布，不读取测试张量。当前学习率/早停策略也按新协议更新，终末后处理沿用E16同版E14流程；因此本轮是E10训练方法迁移，不是仅更换数据的纯因果消融。与E16使用同一成员、评分和后处理，可比较本轮完整训练方案；历史E10的不同面板均值不直接相减。

原参考自由矩形作为监督，不作为求解器输入；MIB修改面积后，它们不保证满足新输入的面积、重叠和MIB约束。接触、相对位置、bbox监督仍按原参考矩形计算，不用修改面积重建并伪称原标签。参考HPWL/bbox分母仅用于计分，派生任务Q为中性时间诊断，不是正式比赛成绩。当前开发500已用于此前多轮研究，属于自适应开发比较，不称独立盲测。

## 训练目标与选模

从E10训练来源独立复制的[losses.py](losses.py)和[occupancy.py](occupancy.py)保留原公式：

`L = center_local + 0.25*shape + 0.25*relative_local + r(t)*(0.5*overlap + 0.5*contact + 0.25*boundary + 0.1*MIB + 0.1*bbox)`，`r(t)=clip(t/2,0,1)`，t按已完成epoch及批次进度计算。中心使用局部尺寸归一化Smooth L1，shape为log长宽比MSE；参考相对位置和组内参考接触始终保留，监督不衰减。几何项在最初2轮加入后固定；没有当前预测布局的动态MST或SciPy建树。

训练仅计算geometry需要的分量，省去无梯度贡献的occupancy计算；相同五例上的loss及全部参数梯度检查验证数学等价。逐轮验证计算完整geometry+occupancy，固定以开发500的`repair=geometry+occupancy`选best和调度。occupancy包含重叠面积、拥挤、32×32网格空白率和紧凑性，沿用E10定义。这个代理不能保证最终Q最优。训练、逐轮验证、可用预算内完整dev诊断都不调用求解器后处理，并单独记录草稿硬合法率。

batch32、AdamW、weight_decay1e-4、梯度裁剪1、float32、CUDA、4个CPU库线程。第1～14轮保护，第15轮建立调度基准。连续3轮无明显改善切换下一学习率，严格为`1e-3 → 2.5e-4 → 1e-4 → 5e-5`，不是统一减半；明显改善门槛`max(1e-5,abs(基准)*0.001)`。连续无明显改善至少8轮、实际下降3次且最低档完成至少一轮训练和验证后才允许早停。资源停止、用户停止与早停分别记录。best/latest保存模型、优化器、调度、随机状态、成员排列与游标及累计墙钟，恢复不重置预算。

## 准备、执行与终末验证

在项目根目录，一个命令依次完成数据准备、训练和冻结best的500例验证：

```powershell
& .\experiments\E17_e10_geometry_v5\launch.ps1 -Resume
```

独立环境`.conda/envs/iccad2026`。训练输出[runs/20261020_e10_geometry_v5_seed0](runs/20261020_e10_geometry_v5_seed0/)，流水线状态与后台日志在[runs/20261020_background](runs/20261020_background/)，缓存在`runs/prepared_v5_e10_cache_v1/`。原E16缓存没有完整原参考矩形，不能供E10的原参考接触监督直接使用；本轮新增独立版本缓存，不覆盖旧缓存。4个spawn进程、各1线程，按原分片聚集每128例一个原子chunk，支持中断复用；训练时读取已准备的张量，不逐步重建图特征。准备完整train/dev，不读取test。缓存绑定数据路径、冻结成员及预处理源码；训练/评价身份包含完整源码快照、设备与预算。

训练阶段最多4小时/200轮，准备和500例验证另计。E17完整吞吐尚未实测，不能保证4小时内收敛；资源上限到期仍冻结当前best做预定终末验证，结果注明资源停止。参考此前同硬件的E10与E16记录，准备可能为数分钟、500例验证约十余分钟；不同负载和样本可能显著改变耗时，不作为承诺。

训练自然结束或预算结束后，由[pipeline.py](pipeline.py)自动调用[final_evaluate.py](final_evaluate.py)，只对同一个冻结best、同一dev_monitor500执行一次。CPU采用2进程×每进程2线程，合计4线程。后处理从E16独立复制E14.certified_rescue.v2：常规目标5秒，按需额外16秒救援，预算为目标而非严格每例上限。结果保存`final_evaluation/results.json`，报告原始/最终硬合法、算术/模块数加权Q、HPWL/bbox与软违反、尾部、回退、异常及时间；异常/不可行以Q=10计入。冻结终末结果不用于换best、续训或再选候选。完成后重复命令仅复用原结果。

在训练运行目录创建`STOP`，训练完成当前batch并保存后退出，不进入验证；准备期间同一STOP也阻止后续阶段，缓存目录的STOP也能暂停准备。验证期间在`final_evaluation/STOP`暂停派发，等待至多2个在途样本落盘。移除相应STOP后重用同一命令恢复；每100步保存latest，强杀可能重放未保存步骤，累计预算账本不清零。源码/数据/设备/预算不兼容时拒绝静默恢复；若需改变身份，先登记迁移。
