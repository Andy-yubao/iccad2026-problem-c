# E29：最小依赖修复器的草稿生成研究

2026-10-21。状态：目标定义，尚未实现模型、冻结正式训练配置或运行新实验。用户最新要求先同步GitHub并整理，暂不尝试研究机制；后续路线在用户继续研究时再推进。本文件给出可审查的目标、建议门槛与下一阶段问题。数值门槛是本阶段提出的研究规格，不是已有结果或经验保证。E25继续冻结，E28保留为归档负面对照；不恢复暂停的E26，不补跑E28其余三组。

## 1. 要解决的问题

学习一个从公开输入生成布局的模型，让它决定主要空间结构、模块形状和位置，处理预放置障碍并协调软约束；输出应已经接近可直接使用。一个固定、确定性、只作小幅排斥的修复器负责少量残余重叠。长期争取原始输出直接合法，但本任务不以完全取消后处理作为前提。

研究对象是完整生成过程，不限于旧草稿上的有界残差。允许推翻坐标表示、拓扑表示和生成顺序。有限步骤的学习式生成或构造解码可以采用，但必须披露实际算法、计算和失败情况；内嵌LP/QP、全局打包、组合搜索或反复优化仍是求解工作，不能改称“模型解码”后省略。

当前没有证据证明一种表示能在本任务所有合法输入上保证可行且低Q。目标是固定条件下可证伪的经验研究，不承诺数学全局最优或对所有输入零失败。

## 2. 已有证据与本轮改变

- [E25](../E25_integrated_baseline/README.md)：固定开发500例全部硬合法，加权Q为1.039577677，平均完整求解0.259486889秒；使用复杂后处理，作为工程参照保留。
- [E27](../../history/20261021_E29_consolidation/experiments/E27_overlap_weight/runs/20261020_overlap1_v5_seed0/analysis.md)：提高重叠惩罚减少草稿冲突，但同版后处理最终加权Q未改善，不能继续只凭重叠代理调权重。
- [E28](../../history/20261021_E29_consolidation/experiments/E28_iterative_draft/runs/20261021_recurrent_full_v5_seed0/analysis.md)：穿透代理降低约90.2%，仍为原始dev500及dev2000零硬合法；线长、bbox面积及分组违反变差。它是冻结旧草稿上的局部修正器，不能代表所有端到端生成机制失败，也不能隔离端点与迭代各自的作用。

本轮将“降低代理”降为诊断，将“绝大多数草稿已合法，剩余冲突可由固定小幅排斥消除，同时保持质量”作为核心可检验目标。最终不以E25复杂修复救回后的Q验收。

## 3. 三种输出必须分开

| 输出 | 定义 | 用途 |
|---|---|---|
| R0：原始草稿 | 公开输入→网络及事先声明的必要解码→坐标；无输出后修复 | 判断生成过程承担了多少工作，记录全部解码成本 |
| R1：简单修复 | 对R0施加下述固定局部排斥，失败直接保留失败 | 本任务唯一最终验收输出 |
| R2：复杂修复 | 可选的冻结E25类后处理，只在另行安排的诊断中使用 | 衡量复杂修复掩盖了多少不足，不进入本任务成功判断 |

R0中的每个非学习操作均列明输入、是否移动模块、是否改变拓扑、循环/候选数与时间。只将公开规格还原和面积参数化称为规格解码；若还包括冲突消除或紧凑化，明确列为构造/求解组件，并通过相同解码器的无学习对照检查贡献。不以组件所在文件或是否可微决定其性质。

## 4. R1修复器的建议固定合同

下面给出首版上限，目的是让“最简单”具有可复现实义。具体数值允许在正式训练前通过最多五例实现/可达性检查修订并登记版本；一经正式比较冻结，不根据候选成绩扩大预算。检查例不能用来宣称总体性能。

1. 只处理已经重叠的矩形对，只沿左、右、上、下作分离平移；尺寸、面积、模块身份与连接均不变。预放置块始终不动；fixed-shape块只有尺寸固定，仍可按公开规则平移。
2. 按固定模块对顺序扫描，选择消除当前冲突所需总平移最小的合法轴向动作；两块可动时平均分配，一块预放置时由另一块承担。平局使用固定方向顺序；产生负坐标、违反锚点或超过位移限额的方向直接拒绝。所有方向都不可用就记未修复，不递归搬开障碍，不回溯。
3. 最多8轮完整扫描；可提前结束。每个可动模块累计平移路径长度不超过其公开典型边长`sqrt(area)`的0.10倍，同时记录净位移；不能用来回移动规避限额。fixed-shape块用公开宽高乘积定义典型边长。分离只使用足以通过现有检查的数值间隔，不能放宽评分容差。
4. 不调用LP/QP/MIP或其他优化器，不重排全局布局、不重新打包、不缩放、不变形、不增加候选择优，不专门修复边界/分组/MIB或优化线长/bbox。修复可能破坏这些关系，损失照实计入最终Q。
5. 运行上限、无可用动作或数值异常都属于方法失败；不启动隐藏救援。主结果保留失败Q=10。原始已硬合法的布局直接原样返回。

无固定outline不意味着可以无限向四周扩张：bbox和线长会惩罚这种行为。预放置障碍、拥挤链或错误拓扑也可能使本合同无法修复；出现这些失败时应改生成机制，不能把它们都交给更强修复器。

## 5. 验收目标与阶段门槛

沿用既有Q公式及`exp(n/12)`模块数权重，不改变官方硬约束、独立复核或本地非负坐标要求。分组、边界和MIB是软约束，必须独立报告并进入Q，不能错误并入硬合法率。

| 阶段 | 建议预先固定的条件 | 能说明什么 |
|---|---|---|
| 机制初筛 | 最多五例：公开输入边界正确、锚点/面积不受破坏，遇到拥挤链和预放置反例时能明确成功或失败；简单修复严格守约 | 实现和可达性证据，不证明泛化 |
| 中间进展 | 固定dev500上R0普通及加权硬合法率均≥90%，R1均≥99%；完整计入失败，并报告质量/膨胀及预算 | 可以跨越当前零合法瓶颈，仍未完成任务；质量明显恶化时不据此扩规模 |
| 最终开发验收 | R0普通及加权硬合法率均≥99%；R1在dev500及同一best的完整dev2000上全部硬合法、加权Q<1.04；平均完整求解<0.25秒，R1平均耗时≤0.025秒且遵守位移/轮次上限 | 在该自适应开发分布实现了本任务目标，尚非封存测试或正式比赛结论 |

0.025秒是总目标0.25秒的10%修复预算，不是机器无关的复杂度保证。R1的触发比例、单例尾部、超预算和每例最大移动都要报告；总体P95为零可能只是多数样例没触发，应另列实际触发子集的统计。原始99%合法是减少依赖的建议目标，不等于原始Q已达标。

失败惩罚使“99%已经不错”不能代替最终验收。若合法部分的加权平均Q为1.02，而失败占总权重1%，则全样例Q为`0.99*1.02 + 0.01*10 = 1.1098`；达到Q<1.04要求失败权重小于约0.223%。因此不从主统计中删除错误/不可行例，也不把合法条件Q当作整体质量。

若R0略低于99%但R1以极小位移全部修好且Q/时间达标，应报告为有价值的阶段成果与目标差距；不能事后改门槛宣布全部完成。若结果表明原目标代价不合理，先说明证据，再与用户重订目标，不静默降低质量或放宽修复器。

## 6. 固定报告与比较

- R0/R1各自报告普通和模块数加权硬合法率、失败类型、全样例算术及加权Q、Q的P95/最大值与最差权重贡献者；合法条件Q另列。
- 记录重叠对数、归一化穿透/相交面积、每例最大冲突簇，以及HPWL gap、bbox面积gap、空白和三类软违反。未合法草稿的几何量只作诊断，不能作为合法质量收益。
- 记录R1触发率、修改模块比例、归一化净位移与累计路径、每例最大移动、轮数、失败和耗时；记录R0构造解码的同类工作量，识别生成器是否依靠复杂内嵌修复。
- 对同一冻结候选保存足够恢复布局的唯一结果，从同一R0派生R1，不择优重采样。初始化、候选数和学习式更新次数都计入预算；在线算法不能访问自由参考坐标、参考评分分母或Q选择输出。
- 完整时间包含公开特征构建、单例网络推理、必要设备传输、全部解码、候选尝试、修复和失败处理；加载/初始化/预热单列，评分和绘图除外。模型生成、解码、R1时间分列，并报告平均/P95/最大值。

E25已有数字只作历史工程参照。新模型与E25比较速度或质量收益须使用同一成员、评分、硬件、精度和资源口径；旧记录是2进程×2库线程，不能与新GPU单例延迟直接计算加速比。批量吞吐另列，不冒充在线单例速度。大规模CPU任务优先总四线程，防止嵌套超配。

核心对照为“新生成器+固定R1”对“冻结E25草稿生成器+同一R1”；必要时加入E28草稿，但不补训。构造解码若是关键组件，加入相同解码器下的确定性贪心/无学习结构选择对照，以及针对关键机制的消融。更换后处理器或扩大预算的结果另列。配对比较保留每例差异、尾部和原始分片聚类的不确定性；有实质收益后再扩到预先固定的三个种子。

## 7. 下一阶段先辨别的机制

目标不预先指定网络架构，先比较不同的失败机制，再决定实现主线：

| 候选假设 | 为什么可能有效 | 反例或停止条件 |
|---|---|---|
| 学习顺序/相对关系，显式构造非重叠结构 | 将不能靠有限罚项确保的离散选择交给可检查的结构表示 | 关系循环、预放置锚点冲突，或表示只能产生质量很差的条带布局；不能笼统声称sequence-pair保证本任务可行 |
| 自回归生成，结合已放模块和公开障碍选择下一块位置 | 决策时看见已发生的占位，避免所有坐标同时折中 | 早期错误造成死路、依赖回溯/全局重排，或逐块生成时间超预算 |
| 以分组/MIB等公开结构生成局部组件，再协调全局 | 尽早保持接触和共同形状，减少简单排斥破坏关系 | 组件与多锚点冲突，组件刚性限制布局质量，或只把求解器藏到组件装配里 |
| 有限步的全局学习式生成，保留改变拓扑的能力 | 避免E28冻结初稿和小位移的可达性限制 | 仍只减少代理而无整例合法进展，或增加步数/采样而不改善同预算质量 |

这些是待筛选的假设，不是四组已获启动许可的正式训练。先查表示能否覆盖困难约束及紧凑低线长布局；同一算法的参考结构/参考形状若用于能力上界诊断，必须标为oracle且仅限train/dev，不计入部署指标。机制未通过前，不把继续加大网络、增数据或调罚项作为默认行动。

## 8. 数据、选模与执行边界

沿用v5 train16,000/dev2,000、固定train/dev_monitor各500及原始分片隔离，复用兼容数据缓存。不得默认将MIB平均面积派生任务中的原参考位置/形状当成完整合法标签；监督兼容性与表示可达性须在正式设计中解释。所有封存测试继续封存，不以目标制定、准备索引或历史授权代替测试授权。

训练和轮内监测不执行R1、R2或其他求解器后处理。正式实现前固定以原始可用性优先、兼顾公开几何质量的选模规则，不能沿用“代理下降即成功”的解释。选模、学习率和停止使用一致固定规则，不随训练阶段改权重择优。batch32、现有四档学习率和早停边界依协议，保存best/latest及累计预算。

每组只对一个冻结best执行一次固定dev500的R0/R1终末评价，并核对同一best的完整dev2000；终末结果不用于更换checkpoint或续训后反复择优。跨候选研究仍属于自适应开发。机制、数据和流程冻结后，封存测试须由用户明确另行发起。

本次没有启动任何新推理、评分、数据准备或训练。下一步是上述机制的表示/反例筛选与最小实现设计；具体模型、选模数值、资源预算和可恢复命令在实现前登记。预计可能超过20分钟的任务只交用户启动，不因“长任务”一词自动取得代跑权限。
