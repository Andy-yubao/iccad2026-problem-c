## 1. 目标与判断标准

当前Q越低越好。因此“提高平均Q”在本计划中统一理解为“提高平均求解质量，即降低平均Q”。不能通过把时间奖励混入Q，掩盖实际布局质量下降。

| 目标 | 如何判断 | 为什么这样判断 |
|---|---|---|
| 平均质量更好 | 同一固定dev100上，逐例Q算术均值下降；同时报告官方块数权重聚合Q | 防止只改善少数案例，或更换平均方式制造提升 |
| 困难案例更稳 | Q最大值下降，Q的P95与最差10例平均Q不恶化；额外统计Q>1.5、Q>2的例数 | 最大值受单例影响，必须与整个尾部一起观察 |
| 速度提高8–10倍 | 相同设备、线程、草稿与计时边界下，总求解时间比达到至少8倍，争取10倍；同时报告后处理时间比 | 用整批总时间之比，不挑选最快单例或平均逐例加速比 |
| 最终硬合法 | 官方与独立硬检查均通过；所有失败、异常、无输出均进入主统计并计Q=10 | 不能用删除难例换质量或速度 |
| 长时间失败可控 | 从求解入口到输出守卫共用总时限，报告超时数、实际最大耗时与回退率 | 单个优化器的time limit不等于整个流程按时结束 |

主验收要求同一个最终配置同时满足以上目标。阶段中可以保留“快但质量尚不足”或“质量好但还慢”的候选，但不能拼接不同配置的最好数字宣称完成。

速度的单例端到端范围为：特征处理、模型前向、后处理、候选选择与最终合法性守卫。模型加载、数据读取、结果写盘等另外报告；对外讨论整批使用体验时也报告包含这些开销的总墙钟。固定草稿重放只测后处理，不能据此直接宣称端到端加速。最终少量重复测量采用预先固定的重复次数与汇总方式，不取最快一轮。

建议的进阶质量目标为均值≤1.20、最大值≤1.8，再争取最大值≤1.5；这些是研究愿景，不是现有能力，也不替代相对同面板旧后处理的改善要求。先在基线阶段登记实际参照、预算和阶段门槛，再比较新方法，不随候选成绩临时放宽。

## 3. 总体顺序

**查清损失发生在哪里 → 建立可靠的早期合法解 → 筛选少数不同后处理机制 → 压缩时间并改善质量 → 识别偏好的草稿 → 必要时调整模型 → 冻结联合方案。**

可靠早期解与主算法设计可以在同一阶段推进；模型需求诊断也可提前积累，但新模型训练应等到后处理偏好有证据。每轮只有一个主要研究问题，避免同时改模型、求解器与预算后无法归因。

### 阶段A：建立可信参照，找到“慢”和“差”的原因

冻结模型、dev_quality100成员、设备、线程与计时口径；保存唯一一份草稿供后处理重放。模型前向重放与坐标精度保持一致，隔离模型随机性。

先用最多5例检查观测记录和计时，再按正式阶段预算运行固定dev100参照。逐例区分：首次合法解、最后一次有效改善、优化器求解、问题构建、数值清理、最终守卫及回退。评价时记录不同时间点的已知最好合法输出，画出质量随时间变化的曲线。

把困难案例分为四类：一直找不到合法候选；候选被最终守卫拒绝；已经合法但软约束/线长/面积很差；继续计算很久却没有有效改善。Q高和耗时长分别排序，并检查它们的交集。

**交付：**一张同步基线表、一张时间分解图、少量具有代表性的失败图；说明最值得先解决的两类问题。没有这些信息，不先围绕24轮迭代或求解器参数反复微调。

### 阶段B：让截止时间到来时，有质量尚可的合法解可交付

当前流程已经保存合法候选并有回退，本阶段要增强这条链，而不是只在外层再加一个超时判断：

1. 开始阶段尽快构造并验证一个合法保底解；随后改进更紧凑、较少软违反的早期解。行排式保底可以防止无输出，但不能独自承担质量尾部目标。
2. 候选进入“最好合法解”集合前，使用与最终守卫一致的硬约束标准；检查浮点清理、负零、接触精度等造成的内外判定差异。
3. 总预算覆盖构造、全部优化子问题、清理、选择与回退，提前给最终守卫留时间。验证实际截止行为；若所用求解器不能及时返回，再考虑可中止的隔离执行，并计入开销。
4. 遇到无进展、反复不可行或数值不稳定时，允许提前切换少数备选构造或布局关系，不在同一坏结构上耗尽预算。

初步研究可用“平均约1秒量级、困难案例最多约5秒”作为预算设计起点，实际档位在阶段A后固定。时限是待验证的工程目标，不能只设置参数就宣称实现。

**通过条件：**困难案例在短预算下也能及时给出经过最终检查的输出；回退是否改善Q必须实测。保存最好代理目标只保证该代理不恶化，不能保证真实Q逐例不恶化，更不能保证所有未知输入的Q上界。

### 阶段C：筛选三个机制不同的后处理方案

每条路线先做最小实现与反例，看到机制信号后再进入dev100，不把三条路线全部做成庞大系统。

| 路线 | 通俗理解 | 预期收益 | 反对它的证据/停止条件 |
|---|---|---|---|
| A：减少重复全局求解 | 继续利用当前全局优化，但复用问题结构，优先约束真正起作用的冲突，减少无效形状轮次 | 保留现有质量来源，同时减少建模和求解成本 | 主要耗时无法减少，或稀疏化导致漏冲突、补约束开销吞掉收益 |
| B：先决定合理排列，再快速压紧 | 把草稿转成模块间的左右/上下关系，快速构造合法布局，再做少量线长、形状和软规则改进 | 用一次较好的构造替代大量试错 | 为保持排列造成面积/线长明显膨胀，预放置障碍和公开软规则处理不了 |
| C：保留全局骨架，只重做困难区域 | 先统一安排空间与公开规则，再对冲突簇及相关邻域做小规模修复，最后全局压紧检查 | 避免每轮都重解全部模块 | 大部分案例的冲突都连成大簇，退化成全局求解；区域边界破坏连通或制造新冲突 |

路线C是新的确定性后处理假设，不恢复旧的局部学习模型。E7草稿可能存在大冲突簇，因此不能预设局部修复一定合适。路线A也不假设当前求解接口天然支持热启动；先核实能力，再选择结构复用或更换接口。

所有路线都必须支持fixed、preplaced与面积等硬规格，保留边界、分组、MIB软规则的真实权衡。使用稀疏冲突约束时，输出仍做全对硬检查；发现遗漏要补约束或拒绝候选。

每条路线至少做两种比较：在目标短预算下比较质量；在相同实际计算预算下比较机制。另与旧方法的正常预算结果比较最终实用价值。画出多个预算点的质量—时间曲线，区分“确实更高效”和“单纯提前停下”。

**选择规则：**保留在质量、尾部和时间上有互补价值的1–2条路线，最多构成一个简单的主流程与备选流程。仅快但质量持续差、仅好但速度无望，均记录原因后停止扩展。

### 阶段D：把候选收敛为同一个快、稳、好的配置

优先让容易案例尽早结束，把有限追加预算用于还有改善希望的难例。是否继续计算，只能看合法输入、草稿冲突、公开约束、候选代理与改善趋势，不能看参考Q。调度本身的耗时也计入预算。

质量优化同时查看线长、面积、边界、分组与MIB，特别检查软违反是否主导尾部。用dev上的官方Q检查候选选择代理与真实目标是否一致；求解时不能调用参考布局、参考HPWL/面积或真实Q来选择输出，也不能用“直到Q达标”为停止条件。

最少保留三项关键归因：去掉新保底链、去掉减少计算的机制、去掉难例调度/新增质量机制。只针对影响结论的机制做消融，不给每个小改动堆一套评价。

**阶段目标：**同一配置在固定dev100上同时降低平均Q和最大Q、控制整个尾部，并达到至少8倍端到端加速；后处理时间、P95时间与实际最长时间分别报告。仍有冲突就保留完整权衡表，不用单一综合分掩盖未达标项目。若已证明主要瓶颈来自草稿结构，可以提前进入阶段E验证模型需求，再返回本阶段验收；不要求冻结E7时就先完成全部联合目标。

### 阶段E：查清后处理偏爱什么草稿，再向模型提出训练要求

这一阶段检验用户提出的“重叠少、空白多反而更好修”假设。不能仅比较不同样本的重叠率与耗时，因为模块规模、预放置和软约束本身就可能影响难度。

先在相同train/dev实例上，从E7草稿产生少数受控变体，例如：保持较紧凑；适度降低重叠并增加可用间隙；将冲突分散为更小的簇；按公开边界/分组规则重新安排局部空间。处理固定与预放置规格，不改变面积、公开约束或允许输入。尽量一次改变一个因素；无法隔离的线长、形状与规则变化如实记录，不把相关性写成因果。

使用同一个冻结后处理和相同总预算，比较最终Q、尾部、求解时间和草稿变换成本。主要观察冲突簇大小、分离方向歧义、形状兼容、公开软规则组织和所需修复幅度，重叠面积与空白率只是其中两个指标。草稿变换能够产生可修输入，不代表模型已经学会生成它。

只有一种草稿变化在足够多同实例对照中稳定改善最终结果，并在不同难度组没有严重反作用，才提出模型需求。例如：“容许一定空白，减少跨组缠绕的大冲突簇”，比“继续降低重叠率”更可执行。

需要新模型时，先固定后处理，训练只改一个有依据的方向；新目标可结合原几何监督与train上的修复反馈。模型继续只输出几何，不增加关系头；不自动恢复E7已终止的occupancy损失或矩形架构。新训练仍用workset_v2的train20,000、固定dev_monitor500、学习率下降、早停及best/latest。

**交付：**一张明确的草稿需求表，写清希望模型改变什么、允许牺牲什么、端到端证据是什么；没有稳定收益就继续使用E7，不为了联调而训练。

若进入模型更新，最后用交叉表核对收益来源：

|  | 旧后处理 | 新后处理 |
|---|---|---|
| 冻结E7草稿 | 当前参照 | 后处理本身的收益 |
| 新模型草稿 | 模型变化对旧流程的影响 | 最终联合方案 |

四格使用相同成员与明确的预算档；额外与旧流程正常预算结果比较。最终重新验收整个联合流程，不能拿只对E7测得的8倍加速替代新模型的实际速度。

## 4. 评估与执行边界

- 默认代码排错最多5例；正式阶段筛选使用冻结workset_v2的dev_quality100，成员不按候选表现更换。额外压力案例来自允许的train/dev，单列报告，不替换主面板或参与主均值。
- 日常先seed0，仅关键随机性结论扩大到固定3种子；确定性路线主要核对输出一致性及少量计时重复，不机械增加重复运行。
- 冻结split_v1与workset_v2，不改评分定义。所有不可行、超时、异常都保留；一次完整面板内的最大值只是经验最差结果，不是未知输入的数学保证。
- 正式冻结后如需扩大dev覆盖或开展测试，另写成员与成本。测试须由用户明确发起，保守排除已暴露及可能在途的测试成员/分片；划分内的分片独立不额外宣称生成家族独立。已暴露测试只保留诊断事实，不伪装成新的独立测试。
- 预计可能超过20分钟的训练/推理只交用户执行命令；交付环境、完整命令、总预算、输出、停止与恢复方式。研究计划不自动启动任何任务或恢复旧运行。
- 实施与证据归本实验及其runs；只共享datasets、scoring、visualization。复制E7算法时登记来源，不能跨实验导入其私有求解代码。权重直接引用原件；保护baseline、活跃任务、冻结索引与唯一checkpoint。
- 每阶段只保留必要配置、逐例结果、恢复记录与少量解释图；阶段结束清理重复/缓存，必要旧证据归history，历史运行记录不改写。

## 5. 阶段结束时应能回答的问题

1. 现有平均质量、质量尾部和耗时尾部分别由什么主导？
2. 哪个新机制在短预算下真正保留或提升了质量，证据是什么？
3. 相同配置是否同时达到了平均Q更低、最差情况更好与8–10倍加速？
4. 后处理需要什么样的草稿，这一需求来自同实例对照还是直觉？
5. 是否确实需要训练新模型；若需要，它对最终联合结果贡献了什么？

阶段交付围绕这些问题，不以运行次数、代码量或新增模型数量衡量进展。
