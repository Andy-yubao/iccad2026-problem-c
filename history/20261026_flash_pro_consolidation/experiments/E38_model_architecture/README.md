# E38：面向高质量draft的模型容量与结构研究

2026-10-22已实现首轮四组容量对照、恢复及终末评价入口，三例实际成员的[功能检查](runs/20261022_implementation_check3_r2/results.json)通过，进入用户授权的后台容量研究。研究问题：**保持现有Loss和数据不变，调整模型深度与信息交互结构，能否生成更容易由轻量后处理快速、稳定修复的draft？** 用户本轮明确授权后台长训练，并要求等待期间准备下一阶段、通过日志查看状态；本授权仅用于当前研究，不延伸到封存测试。

## 研究起点

当前E25使用E17的宽96、4层几何attention模型，497,299参数。E23只将宽度增至160、深度仍为4；训练拟合改善，但开发与最终质量未明确受益。因此值得补充深度对照，不能预设参数越多越好。历史E6/E7/E19/E28也改过结构，但数据、目标、预算不完全一致，缺少当前Loss下的系统比较。来源见[E25模型盘点](../E25_integrated_baseline/runs/20261022_model_training_review/review.md)和[E23记录](../../history/20261021_E29_consolidation/experiments/E23_capacity_geometry/README.md)。

本轮重点调整生成draft的网络。训练目标、权重及前两轮物理项渐入规则沿用E17；保持几何输出接口、面积/固定/预放置解码规则，便于隔离网络贡献。

## 研究方向

| 方向 | 首轮方案与假设 | 反例与停止条件 |
|---|---|---|
| 深度与宽度 | 以96宽×4层为控制，比较96×8、96×12及160×4；更多交互轮次可能比单纯加宽更利于协调布局 | 训练Loss下降而验证不降，或更深网络优化失败，均不能宣称表达能力带来收益；停止继续堆层 |
| 矩形感知交互 | 在attention交互中显式编码当前宽高、相对间隙、交叠及固定锚点关系，使网络看到矩形而不只有中心 | 若同量级参数下不优于普通attention，或碰撞下降伴随接触/边界明显退化，停止该候选；对照历史E7，检验机制而非直接复活旧权重 |
| 连接与约束的分层交互 | 将外部连接端点及group/MIB作为独立交互对象，通过模块与端点/约束对象交换信息，减少预先均值聚合丢失的信息 | 若信息保留只增加成本、没有验证收益，停止扩展；只用公开输入，不增加关系标签或辅助Loss |

先做容量对照，再分别考察两类结构；暂不叠加所有改动。结构候选使用相近参数量的普通attention作对照，报告实际参数、训练开销和CPU单例推理时间。优胜机制再做必要消融，例如去掉矩形特征或恢复聚合端点，以判断改善来自何处。

用户授权等待期间实施下一阶段后，两类结构分别在[E39矩形感知](../E39_rectangular_attention/README.md)与[E40端点/约束分层交互](../E40_endpoint_constraint_tokens/README.md)独立准备，避免修改后台E38的冻结源码。当前仅准备和有界CPU检查，不与四组容量正式训练抢占GPU；主干选择与后续正式运行等待容量结果。

## 如何比较

- **主要筛选用固定验证Loss/代理。** 沿用E17既有的固定`geometry + occupancy`选模代理，统一权重、归一化、成员与聚合，不与训练时带渐入系数的即时total Loss混比。训练反向传播仍为原geometry Loss，occupancy只用于既有监测/选模；另列geometry及各分项。若以后改用纯geometry选模，须单独登记并让本轮全部对照采用同一规则。
- 固定train_monitor500与dev_monitor500，区分欠拟合、泛化差距和优化困难。冻结best后核对完整dev2000的原始代理，避免只依赖监测子集。
- **Loss下降是候选信号，不能单独证明更易修复。** 同步记录原始重叠面积/穿透、冲突簇规模、分组接触、边界/MIB违反及分位数；硬合法率照实报告，不能因非法draft的Q均为10而忽略严重度。
- 每组唯一best冻结后，用同一E25后处理、面板、预算和资源做一次终末500例评价；比较硬合法率、加权Q、尾部、修复位移、救援频率和完整耗时，不按终末Q回头换checkpoint或续训。先验证更好draft能否减轻现有修复负担，再单独制定统一的简化后处理对照；本轮不先改后处理。

## 分阶段与边界

1. **容量初筛：** seed0从头训练96×4、96×8、96×12、160×4。E25冻结权重保留工程参照；新训96×4作为本轮同协议控制，历史E23数字仅作背景。
2. **结构初筛：** 在容量结果基础上，分别实现矩形感知与分层交互两个候选，锁定对照和预算后再训练，避免一开始穷举组合。
3. **确认：** 只有验证代理和草稿诊断出现一致改善的方向，才扩展到固定3个种子与必要消融。若收益只出现在训练Loss，或额外推理开销抵消修复收益，则停止扩容；不据此临时改Loss、换数据或增加教师集。

使用冻结v5 train16,000/dev2,000及既有缓存、原始分片边界不变。固定batch32、四档学习率与现行早停规则；初拟每组最多4小时/200轮，统一记录已见样本数、累计步数与墙钟，预算停止不称为收敛，另看共同步数处曲线。保存best/latest及完整恢复状态，GPU训练与正式CPU计时分开；CPU批量任务默认总计四线程，控制库内并行。

E25及无训练baseline保留。2026-10-22已可视检查的测试draft100例属于已暴露样本，本轮不将其用作验证或独立泛化证据；其余测试继续封存，不新增测试读取。

本轮仍属MIB派生任务的自适应开发研究。**按用户最新要求，本轮不设固定Q/耗时通过线，目标是训练尽可能优秀的模型。** 以固定验证代理为主，结合完整开发集、draft诊断、泛化差距与推理成本比较；最终Q与修复负担另列，不因旧工程阈值中止有价值的模型研究。显著候选继续多种子确认及针对性优化，训练预算停止不冒称收敛；预算内仍持续改善时保留断点，显式登记后续续训，不静默清零预算。其余工作区长期目标保留为背景。

## 已实现的入口与运行方法

- [arms.py](arms.py)、[model.py](model.py)：四种容量配置，普通geometry attention与E25源码一致；深度由配置决定，无新Loss。
- [train.py](train.py)：随机初始化、固定500监测、四档LR、最低档两轮、best/latest、成员游标/RNG/优化器/累计预算恢复。监测`total`也采用成熟固定权重，训练阶段渐入系数另记。
- [cache.py](cache.py)、[data.py](data.py)：只读复用E25原始train/dev张量，按每块`indices`还原成员，检查重复/缺失/顺序，不复制缓存。
- [final.py](final.py)、[freeze.py](freeze.py)：训练结束锁定唯一best，完整dev2000原始诊断按batch恢复；固定500终末评价按实例恢复，2进程×2线程、CPU公开特征/推理/全部修复计入时间。E25冻结模型也走同一入口、同一资源对照。
- [pipeline.py](pipeline.py)、[launch.ps1](launch.ps1)：四组依次运行，stdout/stderr合并到日志；阶段失败立即停，不跳过失败候选。仅执行已批准的容量组，不自动混入下一结构实验。
- [analyze.py](analyze.py)：仅读取已存结果，汇总Loss/冲突/耗时与同入口E25逐例配对区间；不改变best。复制来源见[provenance.json](provenance.json)，模型、Loss与E25后处理独立维护，不跨实验导入私有算法。

在工作区根目录、独立环境`.conda/envs/iccad2026`，一张CUDA GPU运行：

```powershell
& .\experiments\E38_model_architecture\launch.ps1 -Arm all -Resume
```

也可用`-Arm base96x4`、`deep96x8`、`deep96x12`或`wide160x4`单组；单组建议给不同`-Tag`，同一tag的arm/种子/预算/源码身份冻结。`-Stage train`只训练，`-Stage final`只做冻结后的原始/终末评价；同一tag改变阶段须带`-Resume`。已完成训练和评价复用结果，不重训或重评。新训练必须用新tag。

默认每组累计最多4小时/200轮，四组训练合计最多16小时，首次载入、监测计入训练墙钟；终末诊断/评价另计。实际预计时间待三例检查和首轮吞吐记录，不能用历史单组时间当新深度实测。CPU训练四库线程，正式终末2进程×2线程，各层并行受控；GPU训练与正式CPU评价分时。

检查中四组参数量分别497,299 / 982,691 / 1,468,083 / 1,370,771，CUDA峰值分配约1.68GB；该值来自重复两例batch32，不能当全数据显存上限。首次GPU启动耗时单列，不从一次短检查外推整轮训练。检查总计约39.5秒，两步连续与恢复参数差为0；仅一次同dev样例完整求解通过，不能据此判断模型效果。初版诊断遇到Torch/NumPy求和接口不兼容，修正后仍使用相同三例完成检查，没有新增测试暴露。

默认训练输出`runs/20261022_capacity_<arm>_seed0/`，best/latest在其`checkpoints/`，固定监测曲线在`progress.json`；原始完整开发诊断为`full_dev.json`，逐例终末结果为`terminal/results.json`。流水线日志和状态在`runs/20261022_capacity_pipeline_seed0/console.log`与`progress.json`，自动汇总在该目录`comparison.md`/`comparison.json`。E25本轮匹配参照在`runs/20261022_capacity_e25_reference/terminal/`。

创建`runs/STOP`可安全停止整个实验；单组目录或流水线目录内的`STOP`只停止相应范围。Ctrl+C同样请求安全停止。恢复前移除对应STOP，再使用相同`-Resume`命令；累计训练墙钟、样本游标和随机状态保留。源码/数据/设备/预算不匹配会拒绝恢复；后台PID与命令另存启动记录。正式训练开始后保持本实验源码冻结，下一阶段在独立实验实现。
