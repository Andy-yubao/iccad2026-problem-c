# E39 已存结果的失败模式与监督一致性审计

用户要求在下一轮扩深前分析group占比、后处理负担及MIB派生面积与原参考监督的冲突。本轮不训练、不运行求解器、不改冻结数据/Loss/权重，不启动自动跟进。

- 主面板：既有E39 rectangle 96×12 seed0 best49终末dev_monitor500；普通96×12、普通96×4的同成员结果为已存配对对照。
- 监督审计：固定train_monitor500和dev_monitor500，直接复用已验证张量缓存；不读取测试。原输入面积与参考面积的关系需单独核对，不把参考宽高乘积无说明地当作原输入。
- 分开衡量复杂操作：保存的早期投影/打包救援触发、候选求解失败、中心位移、尺寸改变、分离关系改变、耗时与最终软约束/Q。轨迹未记录全部内部步骤及最佳解来源，不把调用次数当作贡献。
- 控制模块数及其触发的既定时间预算档位，报告边际与条件关联、尾部及反例；相关性不当作因果。仅少量救援事件，不拟合复杂分类器。
- 对原参考编码state解码，量化零监督误差时仍存在的物理违约与接触破坏；这些是不可行监督见证，不是最优Loss下界。对现有模型输出计算state梯度冲突，不更新参数。
- 允许一次有界CPU诊断推理以补齐未保存draft，核对已有逐例raw指标；2进程×2线程，总计4线程。预计数分钟，硬上限15分钟。复用图集已存100例坐标，另外400例坐标只存本地npz。
- 输出：analysis.md、summary.json、case_features.csv、target_audit.csv、必要静态图与反例索引。记录来源哈希与实际命令。结果只代表当前自适应开发面板、单种子及一次限时修复轨迹。
