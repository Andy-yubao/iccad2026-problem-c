2026-10-26用户明确授权后台实验，回答“当前架构表达能力充足吗、训练集规模够吗”。这是预先固定的诊断套件，不恢复旧自主任务，不改写E42／E55／E56权重。总墙钟预算12小时，单GPU串行；预计约6–10小时，实际负载会影响完成数量。到预算停止并保留未完成事实，不通过拆任务延长预算。

## 如何避免错误归因

数据规模主实验每个监测块固定500次更新、16000次样本暴露。小数据会经历更多实际遍历，不会因每个“epoch”步数更少而提前降LR。训练文件中的epoch字段表示此监测块，不是一次遍历；同时记录实际optimizer steps、sample draws与effective_data_passes。第15块起原平台规则降LR／早停，允许各组停止点不同，报告必须同时看共同更新步数和各自best，不能宣称实际计算量完全相等。

32例拟合诊断每块64步；目的是观察经验拟合能力，不是训练新部署候选。仍用外部固定dev500同一Loss作best／LR／早停，32例fit_train的最低历史值只作为观测证据，不另存或挑选训练最优模型。保留固定train_monitor500，并分开记录已见／未见成员；记忆实验只有32个训练成员，不能把其余训练池成员的监测值称为训练拟合误差。去正则的配对诊断用于区分正则约束与可拟合性。近似拟合阈值预设为32例平均参考Loss≤1e-3，仅是操作性指标，不等价于全部模块误差为零。未达到阈值也不能直接证明架构无法表达。

## 判读与交付

- 32例能拟合：只说明这批经验样本可拟合，不能证明全分布表达能力充分。
- 32例拟合不好：先看去正则与宽模型对照；优化、早停和预算仍可能是原因，不能直接宣布“网络做不到”。
- 宽模型训练与开发都改善：支持当前容量仍有提升空间；只改善训练：更支持泛化／覆盖限制。
- 8k→16k在两家族均改善：支持当前范围内尚有数据收益；平坦不证明16k已足够，更不能外推所有困难组合。
