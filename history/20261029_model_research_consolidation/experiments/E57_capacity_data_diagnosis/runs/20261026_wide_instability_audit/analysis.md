# 宽模型 seed0 失稳原因审计

结论：已定位到未归一化图聚合残差的逐层数值放大，以及最终读出头的SiLU完全饱和、主干梯度消失。当前证据更支持架构数值稳定性与优化条件共同作用，未发现矩形模型构造、Loss公式或成员错位的证据；尚未完整复现首次触发更新，不能宣称学习率或CUDA实现已被唯一归因／彻底排除。

## 证据范围

只读原best6000步和latest13500步、训练日志、每100步batch_history。CPU短检查使用同五个训练成员，来自重建step6300批次的固定位置，不按标签或Q挑选；未访问测试，未占用GPU，未修改在运行的E57代码、调度或任何原始checkpoint。32大小检查批次由这五例重复组成，不等价于完整原触发批次。

## 时间线与巨值构成

- step6000：batch Loss0.515745、裁剪前梯度范数14.73，开发Loss0.492621；保存为best。
- step6200：batch Loss0.588954、梯度范数13.16。
- step6300：batch Loss1,191,247.125、梯度范数80,189,112；中心输出误差和接触残差同时巨大。
- 此时contact原值2,373,508，乘0.5权重后贡献99.6228%的总Loss；overlap只有0.0000918，不能说本次尖峰由重叠项主导。contact是已记录尖峰的主导项，不证明它是最先的触发因素。
- step6500后网络退化，开发Loss从约19降到约11后停滞，最终状态early_stop。finite与early_stop不代表数值健康收敛。

现有记录分辨率100步，异常启动区间只能缩到6201–6300；没有6299附近的逐步参数和梯度，不能从日志精确恢复首次异常更新。

## 隔离分支干预

下表使用完全相同的失稳后权重、同五例CPU eval输入，只在前向计算中临时屏蔽指定分支，不训练、不保存新模型：

| 前向条件 | 最后读出前隐藏值最大绝对值 |
|---|---:|
| 原失稳模型 | 46,070,512 |
| 屏蔽预测状态反馈 | 7,052,153 |
| 屏蔽图聚合分支 | 68.73 |
| 两者均屏蔽 | 74.38 |
| 正常best模型，原分支 | 31.66 |

原模型路径为 `local(cat(adjacency @ h, mib @ h, group @ h))`，直接加入残差h，没有在该聚合分支前对h归一化或限制分支增益。attention与FFN虽有LayerNorm，并未约束这条路径。失稳权重下h的最大绝对值沿12层约为6→25→64→148→426→1282→3776→12753→54388→245007→1409252→7519280→46070512。分支干预支持它是当前坏状态的主要放大通道；不能把事后关分支直接当作已验证的训练修复。

## 为什么难以恢复

在同五例上，失稳后最后输出头第一线性层的所有自由模块激活前值均为巨大负数，范围约-1.076亿至-39.3万。SiLU在FP32下输出全部为零，最终自由模块输出与head.2.bias完全一致。

因此该次反传中input.0.weight、state_embed.weight、head.0.weight、head.2.weight的梯度范数均为0，只剩输出bias有梯度。正常best的对应梯度均非零。这是对所检查样本的直接观测，不能未经核验外推全16000例每个模块，但足以解释这批样本的主干学习停滞。解码约49%的自由中心坐标轴被截到边界；不是所有矩形同时位于二维原点。

## 已核对与仍未排除的因素

- 实际模型160×12 rectangle、4,055,603参数，源哈希与运行身份一致，模型构造没有退回普通主干；模型源码与E42同一份实现。
- 两个保存检查点参数均有限；没有AMP／FP16训练，记录为FP32。
- 在best权重同五例上，当前等价算子Loss与独立原E42 Loss的总值及输出梯度最大差均为0，暂未发现公式替换错误。
- 五例确定性CPU单步中，裁剪前范数3.47447、裁剪后约1，裁剪实际生效。相同6000步Adam状态下，LR1e-3的参数改变量范数约0.80257，LR1e-4约0.08026；裁剪梯度范数不等于直接限制Adam参数位移，更不保证多层反馈函数的输出不突变。
- 低LR的这一次CPU单步Loss更低，只是局部敏感性线索，不证明低LR可以避免完整原轨迹的失稳，也不是新的学习率实验。
- 以上CPU检查不能完整排除CUDA图／Dropout轨迹、某个批次或精度细节对首次触发的影响。若要唯一归因，需在隔离环境从best6000的完整优化器／RNG状态复现异常区间，并作同批次、同预算、eager/CUDA图和单一参数变化对照。

## 诊断脚本纠正记录

首版CPU单步对照在内存中复用了Adam状态张量，第二个LR对照不独立；这不是原训练代码问题，也没有改写磁盘checkpoint。该首版单步结果不作为证据。后续使用deepcopy保证两组均从6000步相同状态开始，并验证原状态未变。正确对照仅以controls_and_branches.json为准，cpu_results.json中的one_step_CPU_controls字段作废；其来源校验、历史事件和检查点前向记录仍有效。

## 建议修复顺序（尚未启动新训练）

1. 优先单独验证图聚合分支的预归一化或明确残差缩放，限制该路径的层间增益；不把降低Loss权重当作隐藏值放大的根治。
2. 单独做适合宽模型的学习率控制，不能把当前不稳定宽模型当作健康收敛的容量比较。
3. 为巨大但有限的Loss／激活／更新增加诊断和安全保存，必要时回退，记录为失稳而非正常收敛。现有finite检查只拦NaN／Inf，不会拦本次有限巨值。
4. contact的平方残差在状态漂移后放大尖峰，可独立研究鲁棒形式；应与聚合稳定化分开消融，避免混淆来源。

原16组计划保持原样，本审计未改变第二种子或追加正式训练，旧模型和原运行证据均保持原样。
