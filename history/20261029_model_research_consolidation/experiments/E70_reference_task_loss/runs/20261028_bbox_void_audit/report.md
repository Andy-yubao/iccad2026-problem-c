# E70外框、空白与避碰取舍排查

2026-10-28。结论：**E70确实用更大的外框承载了更低的重叠，当前结果不满足用户对紧凑草稿的要求。直接证据优先指向Loss的取舍与内部排布信号缺口；未发现紧凑度计算漏项、单位错误或选模身份错误。** 但“空白普遍大幅增加”与“重叠率只是分母膨胀”并不被数据支持，不能与外框扩大混为一个结论。上一轮复核未独立列出原始草稿外框和精确空白，这是评价的遗漏，本轮补足，不改写旧运行证据。

复用E65/E68/E70已保存的同500例draft，四线程计算**精确矩形并集**，不重新推理或运行后处理。额外复用图库中已存的E42同100例草稿。设A为模块面积之和，B为草稿自身包围盒面积，U为矩形并集面积；空白=B−U，重复覆盖=A−U。区分原成对交面积与重复覆盖，三块相交时二者不同。五例模型短查是后验机制诊断，不是新训练或独立泛化评价。

E70相对E68的同例外框面积平均增加2.742%，498/500例增大；相对E65平均增加2.716%，497/500例增大，属于广泛退化。表中500例交面积与旧报告dev2000数值略有不同，不能混用。

相对E68，只有48/500例空白面积增加，总体空白比例下降；相对E65有330/500例空白面积增加，平均空白／外框只上升0.164个百分点。**E70更好地铺开了原本重叠的面积，但没有在保住原外框的同时完成排布。** 因此不应将E68这个原本更差的候选作为质量验收的唯一对照。

用户实际看的同100例图库也支持这一取舍：相对E42，98/100例外框增大，平均增幅2.579%；空白／外框均值从9.933%升至10.082%，63/100例空白面积增加；成对交面积从6.366%降至4.067%。空白均值增加不大，但外框增加明显而且普遍，达不到用户要求。详见[图库同例证据](gallery100_E42.json)。

这里重叠指标的分母始终是固定模块总面积A，**不随外框B变化**；三组同例A已核对一致。故下降不是简单“扩大分母”造成的假象。外框扩大让模块在空间上散开，是真实几何取舍，不能据此证明没有避碰收益；同样不能把这个收益等同于更好的紧凑布局。

## 3. 实现及五例梯度检查

检查[losses.py](../../losses.py)、[batches.py](../../batches.py)、[model.py](../../model.py)、原E68八项Loss、解码与监测路径。新紧凑度实际为`0.25 × max(B/A−1,0)`，有效节点mask、面积单位、包围盒min/max及反向路径均存在，未见误用reference面积或漏乘权重。五例独立几何计算与该项最大差约8.3e−8。模型推理复现已存draft的最大坐标差0.000458物理单位；新总Loss与完整开发记录最大差约2.0e−6，符合CPU／批处理路径浮点差异，未发现模型身份或计算路径不一致。

五例按E70/E68外框增幅的10/30/50/70/90百分位事先选定，index423/48/474/107/449，模块数102/116/22/40/52。不根据短查结果重挑样本，最多五个唯一案例，无参数更新。

**问题一：固定总Loss在当前局部更偏向保住避碰收益。** 对可移动模块中心向内缩1%，宽高不变，预放置坐标由解码保持，五例外框与空白比例都下降，但五例总Loss全部上升0.48%～2.06%。例如index423外框／A从1.04758降至1.03850，空白比例从8.120%降至7.814%，总Loss却从0.226848升至0.231523。五例平均：避碰两项增加约0.006220，紧凑项只节省约0.002356，其余项合计也不足以抵消。四例的无穷小径向导数直接支持继续向外扩张；另一例无穷小与1%有限步的符号不同，说明非光滑接触与局部尺度重要，不能说每一点都偏向扩张。

**问题二：外框惩罚没有直接告诉内部模块去哪里填空。** 五例中紧凑度中心梯度都只作用于2个模块，而可移动模块分别有98/114/21/38/51个。原因是`min/max`包围盒只对当前极值模块提供直接位置梯度；内部模块即使围出空洞，只要不改变极值，就没有这一项的直接信号。共享网络参数仍可间接影响其他输出，不能说它们绝对学不到紧凑化。但仅靠外框标量无法提供完整的内部重排方向。

**问题三：Loss变化同时削弱了位置关系锚定，新增的任务项不能替代填空约束。** E68的位置权重1降为E70的0.25，且小模块新增尺度下限；参考近邻相对位移项删除，指定reference接触改为公开分组MST。这符合本轮“reference只用于位置/形状”的设计，不是实现遗漏。线长只约束有连接的模块，分组MST只连通公开组，二者都不要求所有自由模块协调填满空隙。没有分组/弱连接模块尤易缺少整体排布方向；此前无直连位置与近邻关系误差上升与此一致，但本轮没有单项消融，不能精确分配各项贡献。

不要仅凭权重数字断言面积惩罚“比以前小”：旧bbox为`0.1 × log(B/B_ref)^2`，新项公式、尺度与目标均不同。新紧凑项确实有效地提供向内压力，问题在于它与新避碰及其他项的实际梯度平衡，以及内部协调方式。把问题概括为“漏加面积Loss”是不准确的。

**架构限制是候选解释，不是已证实的唯一根因。** 同一E68端口主干能在旧Loss下产生更小外框，故现有对照更支持优先处理目标／优化路径。当前逐模块预测中心和长宽比的解码只硬保证面积、固定规格与预放置，没有构造级的整体装填保证；仍允许“向外散开”作为降低碰撞的自由度。不能从本轮直接断定增加层数、token或容量会解决问题。

## 4. 为什么不应直接压缩、续训或只加一项空白Loss

简单整体压缩会重新引入碰撞，五例已出现这一反例。需要的是在受控外框里进行**协调重排／改形／填空**，不能把缩放当修复。训练过程也并非始终扩张：开发紧凑度残差从第1轮0.234降到best71的0.0677；这里的外框退化是最终模型相对历史对照，而非单调训练轨迹。继续降低当前总Loss不保证回到用户要求的取舍。

单独增加精确空白标量也不自动带来新机制：恒有`(B−U)/A = B/A−1 + (A−U)/A`。在A不变时，它与外框和重复覆盖密切耦合；一块不重叠的内部模块在外框里平移，U和B都不变，空白总面积Loss仍不给它“向哪个空洞移动”的方向。若采用密度／空间势等方法，须检查其梯度是否真能推动内部模块，并排除随自身外框放大而稀释目标的捷径。

建议下一步先冻结主干、数据、seed0与reference读入边界，设计一个**固定目标下的受控外框＋内部协调填空**对照；必要时比较损失侧机制与构造/修正侧机制，而不直接加大模型。公共总面积A只是下界，预放置和组约束可能令B=A不可达，不能把A硬当作所有案例可行外框。需要先用反例检查“相同或更小外框内减少碰撞”的可行改进方向，再固定公式、权重与验收口径；五例本身不足以确定新系数，也不能据此宣称方案已成功。

本轮到诊断结束，不修改已训练Loss、不续训、不自动启动新实验，不重新用Q选checkpoint，测试封存。保留原权重作为反例证据，E42继续冻结。
