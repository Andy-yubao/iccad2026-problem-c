# 工作约定

- 开始先读 README.md、docs/protocol.md、docs/workspace_structure.md。这里只保存现行边界，不累计实验进度和过期授权。
- 当前研究是独立修正器：冻结布局器L，F读取公开问题和当前草稿，全局并行修正。早期以一次F为主要训练/选模/评价口径，多次调用仅辅助；不使用逐模块自回归。
- 草稿研究以用户同例图评价为重要依据，固定Loss和几何指标解释变化，终末Q为辅助。默认同100例reference／L／F×1／最终后处理，统一ID与尺度，无评分控件，不自动打开界面。
- 保持原始split_v1的80/10/10分片归属与所有冻结索引。新实验明确成员版本、公开面积变换和来源模型；默认16k/2k/2k、固定train/dev各500监测，扩展成员须另行登记。测试默认封存，只有用户明确发起测试才开放。
- 网络只读公开规格与允许的草稿；reference自由位置、标签、分母不作网络输入。L可有reference监督，F以已登记的任务与输入意图目标为主。
- 每阶段Loss固定，反传、train/dev监测、best、LR和早停使用同一函数。布局器前/后训练只在登记边界切换；F独立登记。具体LR、权重和预算归实验计划，历史规则不自动沿用。
- best与latest分别保存；阶段内恢复保留优化器、RNG、数据排列/游标、调度及累计预算。变更目标、数据或数值路径必须登记迁移或新运行，不覆盖旧证据。
- 默认最多5个相关实例做实施短检。正式训练与评价按登记面板运行；不堆重复测试，不用dev扫多组系数。
- 长训练默认交付命令；用户明确授权后可在指定范围后台运行。用户要求停止时立即阻止后续阶段、安全保存并核实退出。自动唤醒和额外候选需明确授权。
- GPU工程以吞吐/每轮耗时为主要指标，按docs/gpu_training.md检查；运行内保持batch、精度、样本顺序和数学目标，工程变更先检验实际更新与恢复。
- 实验目录用En_xxx，源码、方案、证据与runs同属该实验。复用datasets、scoring、visualization；模型/Loss/搜索算法独立维护，不跨实验导入私有算法。布局图统一调用visualization。
- 使用独立conda环境；数据由protocol/paths.json解析。原件、有效缓存、活跃运行和唯一权重保护；旧必要证据归history，清理先检查引用与路径。
- 源码用本地Git main和origin管理；数据、环境、缓存、权重和凭据不入库，不重置用户已有改动。
- 主动质疑未经证实的解释，以消融、反例或对照说明机制；区分草稿/后处理、合法性/质量/时间及开发结果/正式比赛成绩。
