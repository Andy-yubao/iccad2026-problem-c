# GPU训练工程路径

更新：2026-11-01。目标是更高样本吞吐和更短每轮耗时；利用率、功耗和显存仅作解释，不追求制造100%占用。

## 顺序

1. 先分解CPU组批、传输、前后向、优化器、监测和存盘；记录步耗时P50/P95、样本/秒、完整epoch及初始化时间，注明设备功耗/频率和其他进程。
2. 复用校验过的张量缓存，预先打包公开输入和来源草稿；仅传Loss/网络所需字段，避免标签/参考坐标无用途搬运。CPU缓存优先用pinned staging与non_blocking，条件允许再预取重叠。公开模块/端口mask不变。
3. 用固定形状或有限形状桶减少分配；不静默重排样本或更改batch。全量GPU常驻必须先算专用显存余量，保留Adam、激活、捕获和监测空间；防止共享显存换页。E95首轮已约12.6/16.3GiB，不直接把全库塞入GPU。
4. 合并有限性/梯度/参数检查和日志标量，减少逐参数bool、item、float造成的CPU同步。Adam前保留数值门禁，失败不跳批；详细分项按登记频率回传，监测一次传回向量后在CPU汇总。
5. 对可捕获的固定执行路径接入CUDA graph，常量/缓冲预创建，预热与捕获不做优化器更新、不计实际训练步，保存/恢复RNG。先捕获前向+同Loss+反向+裁剪，必要的门禁与原AdamW在重放后执行。
6. 逐项排除不支持捕获的操作。PyTorch2.7.1的prod反向可能包含主机分支；数学等价替换也要验证浮点梯度与一步更新。分组树等循环包含很多小核，应计量后处理，不能只压缩Python代码。
7. 监测批量化、原子best/latest和周期保存，降低重复存盘。异步保存必须先取得一致CPU快照，不能让后台线程读取正在变化的模型。绘图/终末求解放训练结束后。

## 验证与变更边界

- 默认同5个相关成员；比较前向和逐项Loss、参数梯度、真实Dropout/Adam更新、保存恢复后的下一步、padding及非有限值拒绝。
- 工程控制保持成员/顺序、batch32、FP32、Loss、优化器和停止口径；若有数值差异，登记新引擎与容差证据，不冒称逐位一致续训。不能关闭安全检查来提升吞吐。
- 混合精度、TF32、大batch、近似注意力或减少监测等分别登记为新配置，不混入等价加速结论。
- 短微基准不代替完整epoch测速，不用不同功耗/并发负载下的墙钟宣称加速。

## 已有经验与当前缺口

[E52历史工程](../history/20261026_flash_pro_consolidation/experiments/E52_training_throughput/README.md)在旧结构同条件微基准171.3→67.1ms/步，约2.55倍；不能直接套用到E95完整训练。

E95首轮为普通eager路径：逐批Python组装、逐草稿传输、逐参数有限性检查、多个标量回传，尚未接入CUDA图。十次短采样25%–98%、中位57%，只能说明该窗口有波动；各瓶颈占比需实际分解。后续优化必须明确实施了哪些、检查了哪些，不能仅写入本文就称已完成。

E95本次修复已实装pinned公开组批、整批草稿传输和合并检查，按实际尺寸运行eager；token>448重算attention核心，保持FP32。统一512端口CUDA图未通过显存准备，失败证据保留。五例压力检查（32×120×512 padding）峰值allocated5236MiB/reserved7004MiB，参数更新及恢复下一步检查通过。含组批四步微基准原参考213ms/步、打包231ms/步，未证明提速；整轮吞吐仍需正式日志验证。详见[E95检查](../experiments/E95_single_pass_corrector/runs/preflight_v2/results.json)。

E95后续工程修复验证了Windows当前构建的FP32 efficient SDPA（Flash不可用），配合32×120×480 CUDA图，避免大attention重算。同五例真实断点更新与新图重建恢复通过；最大尺寸微基准613→350ms/步，非整轮保证。捕获使用新建对象加载同权重/Adam，释放遗留诊断反向图，避免旧eager流依赖干扰。详见[E95工程检查](../experiments/E95_single_pass_corrector/runs/20261101_engine_repair/check.json)。

端口逐token全局交互尚无独立收益证明，不设为默认必要条件。后续[输入压缩对照](../experiments/E95_single_pass_corrector/port_compression_proposal.md)准备32区域聚合及逐模块摘要两档；Loss/评价仍使用原始完整公开端口线长，当前活跃运行输入不变。
